# Монитор брендов Casher

Раз в сутки обходит Reels всех брендов из Google-таблицы «CASHER БРЕНДЫ ДЛЯ АНАЛИТИКИ» и показывает в дашборде, что у них сейчас залетает.

## Как пользоваться (Даня)

1. Раз в день дважды щёлкни `ЗАПУСК.bat`. Откроется отдельное окно Edge и само пойдёт по брендам, примерно 70 минут на ~410 аккаунтов. Окно можно свернуть, только не закрывай его. Прервалось - запусти ещё раз, продолжит с того же места.
2. В конце сам откроется дашборд. В любой момент позже его открывает `ДАШБОРД.bat`. Пока смотришь, не закрывай чёрное окно: в нём работает превью - наведи на обложку, и ролик проиграется без звука. Видео при этом не скачиваются и не хранятся, на лету берётся только ссылка на ролик. Если открыть `dashboard.html` двойным щелчком, всё работает, кроме превью.
3. Новый бренд добавляешь строкой в Google-таблицу (колонка Instagram с @ником). Со следующего запуска он попадёт в сбор.
4. Если Instagram разлогинил окно сборщика, запусти `ВОЙТИ В INSTAGRAM.bat` и войди руками. Лучше технический аккаунт, не основной.
5. `ГЛУБОКИЙ СБОР (один раз).bat` - разово докручивает вкладку Reels каждого бренда до конца (~100 роликов на бренд, 2-3 часа). Нужен, чтобы период «всё время» и «3 месяца» был полным: обычный ежедневный сбор видит только ~18 последних роликов, у частых постеров это неделя-две. Прервался - запусти снова, продолжит с места.
6. `ОБНОВИТЬ ДАШБОРД.bat` пересобирает страницу без нового сбора, например после правки разборов в `notes.json`.

Папку `_session` и файл `proxy.txt` никому не отправлять: там вход в технический Instagram и пароль прокси.

Сборщик работает под техническим аккаунтом (с 20.10) и ходит в Instagram через прокси из `proxy.txt` (Амстердам). Без прокси - `py -X utf8 monitor.py --no-proxy`.

## Что в дашборде

- **Залетает сейчас** - ролики за последние 3/7/14 дней, которые уже обогнали медиану своего аккаунта (по умолчанию в 3 раза и больше). Главная вкладка на каждое утро.
- **Новое** - всё, что бренды выложили с прошлого среза.
- **Все ролики** - вся база роликов с выбором периода: 7/30 дней, 3 месяца, год, всё время или свои даты. Кратность «любая» - все ролики, «×3» - только залёты. При клике на бренд открывается здесь же, за всё время.
- **Бренды** - все аккаунты: медиана, лучший залёт, сколько залётов за 30 дней, частота Reels. Нажми на строку - откроются ролики этого бренда.

Как считается:
- **Медиана** - по 18 последним Reels аккаунта (без закреплённых и роликов младше 3 дней).
- **Кратность** - просмотры ролика, делённые на медиану.
- **Прирост** - сколько ролик набирал в сутки с прошлого замера. Первые точки - замеры 11.10 и 14.10, дальше каждый ежедневный срез.

Разборы роликов (формат, хук, почему залетело, как применить для Casher) лежат в `notes.json` по коду ролика и показываются на карточке:

```json
{"DcoTWXVtobn": {"format": "...", "hook": "...", "why": "...", "apply": "..."}}
```

## Для программиста (перенос в Amarix)

Сейчас это работает локально: Python + Playwright (Edge), без серверов и сторонних сервисов. Для переноса нужны три вещи.

### Запуск с нуля

```bash
pip install -r requirements.txt
playwright install chromium        # на Windows можно не ставить: берётся установленный Edge (channel='msedge')
cp proxy.example.txt proxy.txt     # вписать прокси, или задать переменную MONITOR_PROXY
python monitor.py --login          # открыть окно и войти в технический IG-аккаунт руками (сессия -> _session/)
python monitor.py --no-open        # сбор + пересборка дашборда
python monitor.py --serve          # дашборд с превью на http://localhost:5612/dashboard.html
```

Без сбора дашборд открывается на примере данных из `sample/` (12 брендов, урезанная выгрузка 20.10).

На Linux-сервере в `launch()` надо убрать `channel='msedge'` (будет Chromium из Playwright), а сбор запускать с `--hidden` по cron раз в сутки, например `0 6 * * * cd /opt/monitor && python monitor.py --hidden --no-open`. Сессия IG лежит в `_session/browser_tech` (профиль браузера) и `_session/ig_cookies.json`. Если IG разлогинит, сборщик остановится с сообщением, тогда снова `--login`.

**Прокси.** `launch()` в `monitor.py` передаёт прокси во все окна браузера: сборщик, вход, превью, докачка обложек. Chromium не поддерживает SOCKS5 с логином и паролем, поэтому указывать нужно HTTP-адрес: `http://user:pass@host:port`. Флаг `--no-proxy` отключает прокси.

**Сборщик** - `monitor.py`, функции `collect` / `grab_one`. Он открывает `instagram.com/<ник>/reels/` под залогиненной сессией, дважды прокручивает и снимает плитки: код ролика, текст просмотров, закреп, обложку. Дата публикации вычисляется из кода ролика (`posted_at`), отдельного запроса не нужно. Темп - одна вкладка, пауза 2,5-5 с между аккаунтами (`PAUSE`), ~410 аккаунтов за ~70 минут. Если IG просит подождать или 6 аккаунтов подряд пустые, сбор делает паузу или останавливается и при следующем запуске продолжает с места. Список брендов - CSV-экспорт публичной Google-таблицы (`SHEET_CSV`), минус `exclude.txt`.

**Данные** - `data/latest.json`, его же читает дашборд через `dashboard_data.js`.

```
day, built, started, finished   дата среза и время сборки
total, ok                       брендов в таблице / собрано в срезе
days                            список всех срезов
accounts[]: h, name, region, country, seg, scale, note, site, client, src, own (1 = наш аккаунт),
            state (ок / не найден / закрытый / ошибка / нет в срезе),
            f (подписчики), med (медиана), n, n30 (Reels за 30 дн.), last (дата последнего Reels),
            best30 (лучшая кратность за 30 дн.), hot30 (залётов x3+ за 30 дн.), mx30 (макс. просмотры за 30 дн.),
            nall (роликов в базе), since (дата самого старого ролика в базе)
reels[] (вся база, включая ролики из прошлых замеров): code, h, views, x (кратность), age (дней), posted, gain (прирост в сутки),
            prev (дата прошлого замера), th (обложка, ссылка IG CDN живёт несколько дней), new, note,
            seen (если ролика нет в сегодняшнем срезе - дата последнего замера просмотров)
```

Обложки хранятся локально в `thumbs/<код>.jpg` (~15-25 КБ), потому что ссылки IG CDN живут несколько дней. Новые качаются при сборе. Недостающие докачивает `monitor.py --thumbs`: сначала по ссылке из сетки, иначе со страницы `instagram.com/reel/<код>/embed/captioned/`. Эта страница рисуется скриптом, поэтому открывается через окно браузера, а не простым запросом.

История просмотров по дням - `data/history.json` (`код -> {h, v: {дата: просмотры}}`), сырые срезы - `data/raw/ГГГГ-ММ-ДД.json`. Залёты x3+ дополнительно выгружаются в `data/zalety.csv`.

**Интерфейс** - `dashboard.html`, один файл без библиотек. Это макет того, что должно быть в дашборде Amarix: вкладки, фильтры (регион, сегмент, источник, свежесть, кратность, просмотры), сортировки, карточки, таблица брендов.

**Превью роликов** - `monitor.py --serve` поднимает локальный сервер (порт 5612): отдаёт папку и `/api/video?code=<код>` -> `{url}` прямой ссылки на mp4 в IG CDN. Ссылку берёт скрытый браузер без входа со страницы `instagram.com/reel/<код>/embed/`, а если бренд запретил встраивание - запасной путь под входом (`fetch("/reel/<код>/")` -> `video_versions`). Видео и картинки скрытый браузер не грузит. Ссылки кэшируются в `data/video_cache.json` до срока из параметра `oe`. Дашборд заранее запрашивает ссылки для видимых карточек, поэтому видео стартует через 0,2-0,6 с после наведения. В Amarix это один такой эндпоинт на сервере.

**Что не в репозитории** (`.gitignore`): `_session/` (вход в IG), `proxy.txt` (пароль прокси), `data/` (история и срезы), `thumbs/` (~9 500 обложек, ~190 МБ), `dashboard_data.js` (генерируется `build()`).
